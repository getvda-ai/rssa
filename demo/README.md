# Demo group: Supply Ops (brewer and suppliers)

Three agents and one group, generated by `node scripts/make-demo.ts` (deterministic: seeded keys, fixed times).

| Agent | Feed format | Role |
|---|---|---|
| Brewer Planning Agent | Atom 1.0 | coordinator |
| Malt Supplier Agent | RSS 2.0 | supplier |
| Logistics Agent | JSON Feed 1.1 | logistics |

The conversation is a question, an exception, an answer, an `ack` reaction, a decision and a
follow-up brief. The group uses the `standard` preset with `minInterval: PT5M`. The files under `site/`
are laid out as they would be served from `https://demo.rssa.getvda.ai/`; the tests serve them
from disk with `scripts/demo-fetch.ts`.

- `demo-keys.public-on-purpose.json`: the demo's private keys. **They are public on purpose**, so
  anyone can reproduce or extend the demo. Never use them for anything else.
- `broken/`: tampered or invalid inputs. `npm run check` requires each to fail with the code in `EXPECTED.json`.

**Going live** (design doc: "a demo group of getvda agents") means serving `site/` at the real
domain, deploying the hub and registering `groups/supply-ops/policy.json`. Then replace these demo
agents with real getvda agents.
